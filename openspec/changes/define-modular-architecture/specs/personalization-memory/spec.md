## Purpose

定义隔离、可追溯的用户记忆和个性化决策合同，使个人偏好能改变研究策略与最终排序，同时绝不切碎或污染公共查询和证据资产。

## ADDED Requirements

### Requirement: 四层用户记忆
系统 MUST 将用户相关上下文区分为以下四层，并为每项记录保存来源、作用域、置信度（如适用）和更新时间：

1. 会话记忆：当前问题、地点、时间和临时约束。
2. 显式偏好：用户明确表达的喜欢、忌口、预算和出行要求。
3. 推断偏好：由收藏、忽略、点击和反馈推断的长期倾向。
4. 策略反馈：用户对研究深度、来源可信度和结果风格的反馈。

#### Scenario: 记录明确忌口
- **WHEN** 用户明确表示“不要辣”
- **THEN** 系统 MUST 将其记录为可追溯的显式约束或偏好，而不得仅作为低置信度推断

#### Scenario: 从行为推断偏好
- **WHEN** 系统从多次收藏或忽略行为推断长期倾向
- **THEN** 该记忆 MUST 标记为推断、携带置信度，并保持低于显式信息的优先级

### Requirement: 确定性的冲突优先级
筛选和排序发生冲突时，系统 MUST 按以下优先级决策：显式硬约束高于当前会话要求，当前会话要求高于稳定的显式偏好，稳定显式偏好高于推断偏好。策略反馈只能影响研究方式和结果呈现，不得绕过更高优先级的内容约束。

#### Scenario: 会话要求覆盖稳定偏好
- **WHEN** 用户长期偏好低预算，但在当前会话明确要求商务宴请且给出更高预算
- **THEN** 当前会话预算 MUST 用于本次筛选，稳定偏好仍保留供后续会话使用

#### Scenario: 显式约束覆盖推断偏好
- **WHEN** 点击历史推断用户偏好辣味，但用户明确要求本次不要辣
- **THEN** 系统 MUST 过滤不满足显式约束的候选项，而不是仅降低其排名

### Requirement: 公共证据与用户记忆隔离
公共 Evidence、Query Family 身份、公共特征和公共评分 MUST 对所有获准用户共享；用户记忆只可影响当前用户的研究深度、来源策略、过滤、权重和最终排序。系统 MUST NOT 因用户偏好创建语义重复的公共 Query Family 或回写公共事实。

#### Scenario: 用户偏好不改变 Family 主键
- **WHEN** 两个用户对同一公共查询分别偏好清淡和重辣
- **THEN** 系统 MUST 复用同一 Query Family 和 Evidence Bundle，并生成两个隔离的个性化决策结果

#### Scenario: 用户纠正个人偏好
- **WHEN** 用户更正自己的预算或口味
- **THEN** 系统 MUST 更新该用户的记忆与后续排序，不得修改餐厅的公共价格、口味证据或其他用户结果

### Requirement: 用户级访问隔离
系统 MUST 将持久用户记忆、推断记录和个性化决策绑定到稳定用户主体，并在所有读取、写入、导出和删除操作上执行用户级授权。日志、指标、缓存键和事件 MUST 不暴露另一个用户的私有记忆。

#### Scenario: 跨用户读取尝试
- **WHEN** 一个用户请求读取或修改属于另一用户的记忆
- **THEN** 系统 MUST 拒绝该操作，且不得通过响应、缓存命中或日志泄漏私有内容

#### Scenario: 匿名或临时会话
- **WHEN** 请求没有可持久化的用户主体
- **THEN** 系统 MUST 将记忆限制在当前会话作用域，并不得错误合并到其他匿名会话

### Requirement: 个性化研究策略与最终重排
系统 MUST 从有效记忆生成版本化的个性化策略输入。策略可在 Domain Contract 和请求授权允许的范围内调整搜索深度、来源优先级、可信度阈值、硬过滤和排序权重；公共候选事实与公共评分必须保持不变。个性化结果 MUST 能解释使用了哪些记忆类别和策略版本，但不得在客户端未授权时暴露敏感记忆值。

#### Scenario: 本地性和游客友好度采用不同权重
- **WHEN** 本地用户与首次到访用户使用同一公共候选集合
- **THEN** 系统 MUST 分别应用本地性/长期口碑权重和游客友好度/交通便利权重，并保留同一公共评分输入

#### Scenario: 策略反馈要求更深研究
- **WHEN** 用户明确要求更高来源可信度和更深研究
- **THEN** 系统 MUST 调整该用户请求的停止条件或来源阈值，不得改变 Query Family 身份或其他用户的刷新策略

### Requirement: 个性化不得扩张能力集合
任务的有效来源和工具集合 MUST 等于 Domain Contract allow-list、请求主体授权集合和 Personalization 所选子集的交集。Personalization 只能删除、收窄或重排已授权能力，MUST NOT 启用 Pack 未声明、主体未授权或 Gateway 未注册的 Connector/Tool。

#### Scenario: 记忆请求未授权来源
- **WHEN** 用户记忆或策略反馈偏好一个不在活动 Domain Contract allow-list 中的来源
- **THEN** 系统 MUST 忽略或明确拒绝该能力请求，并不得调用对应 Connector

#### Scenario: 个性化收窄来源
- **WHEN** 用户在多个已授权来源中明确排除其中一个
- **THEN** 系统 MUST 可从有效能力集合中移除该来源，但其他用户和 Domain Contract 本身保持不变

### Requirement: 不确定记忆的保守处理
缺失、过期或低置信度推断记忆 MUST 不得被当作硬约束。系统 MUST 使用领域默认策略或请求澄清，并 MUST 在排序决策中区分“没有偏好”与“明确无偏好”。

#### Scenario: 低置信度推断与候选冲突
- **WHEN** 低置信度推断偏好会排除大量满足当前请求的候选项
- **THEN** 系统 MUST 不将该推断作为硬过滤，并保留可说明的默认或澄清路径

#### Scenario: 热缓存不可用
- **WHEN** 用于窗口、摘要或召回的派生缓存不可用但权威记忆记录可读
- **THEN** 系统 MUST 从权威记录重建派生数据或按明确策略使用非个性化路径，不得把其他用户的缓存内容当作当前用户记忆

#### Scenario: 权威记忆存储不可用
- **WHEN** 权威记忆记录或其事务提交不可用
- **THEN** 系统 MUST 不确认新记忆写入，不得以缓存作为新的权威事实，并 MUST 返回稳定失败或明确的旧版本读取状态

### Requirement: 记忆更新的幂等与可追溯性
来自同一用户动作或反馈事件的重复投递 MUST 产生幂等记忆更新。每次显式或推断记忆变更 MUST 能关联其来源事件和策略版本，以支持纠正、删除和结果调查。

#### Scenario: 重复点击事件
- **WHEN** 同一点击事件因重试被投递多次
- **THEN** 系统 MUST 只计入一次推断更新，不得人为放大偏好置信度

#### Scenario: 调查一次个性化排序
- **WHEN** 用户或运维人员在授权范围内调查某次排序
- **THEN** 系统 MUST 能关联当时使用的记忆版本、公共 Bundle 版本和排序策略版本

### Requirement: 记忆事实与派生索引分离
原始会话消息、结构化记忆记录、记忆变更事件、偏好快照和用于派生更新的 outbox 事件 MUST 由同一权威事务保存。缓存窗口、滚动摘要、语义向量和召回索引 MUST 是带模型或规则版本的派生数据，MUST NOT 替代原始记录、来源事件或用户纠正状态。系统 MUST 在权威事务提交后才确认记忆写入，并 MUST 在提交后通过可重试的 outbox 处理失效或回填派生缓存。派生缓存 MUST 携带权威记录版本，不得覆盖更新的记录。

#### Scenario: 记忆写入后进程立即退出
- **WHEN** 系统已经向用户确认一项显式偏好写入且进程随后退出
- **THEN** 重启后的系统 MUST 从权威记录恢复该偏好，而不得依赖退出前的进程内任务或缓存写入

#### Scenario: 权威提交后缓存失效前崩溃
- **WHEN** 权威事务已提交但进程在缓存失效或回填前崩溃
- **THEN** 重启后 MUST 重放 outbox 并按权威版本失效或回填派生缓存，不得让旧缓存覆盖已提交记忆

#### Scenario: 语义索引丢失
- **WHEN** 记忆向量索引损坏、过期或被删除
- **THEN** 系统 MUST 能从权威记忆记录重建索引，并不得因此丢失、改变或跨用户合并记忆事实

#### Scenario: 派生语义配置切换
- **WHEN** 语义索引需从一个已激活配置切换到另一个配置
- **THEN** 系统 MUST 保留权威记忆与原配置索引，在新索引回填完成并通过验证后切换，且回滚不得改变记忆事实

### Requirement: 有界会话热窗口
会话热窗口 MUST 最多保留最近 20 条会话消息且有效期为 24 小时。热窗口的淘汰或过期 MUST NOT 删除权威会话事实，并 MUST 支持从权威记录重建窗口。

#### Scenario: 会话热窗口淘汰
- **WHEN** 会话接收第 21 条消息或最近消息超过 24 小时
- **THEN** 系统 MUST 仅淘汰或过期热窗口内容，并 MUST 使用权威会话事实保持后续读取与重建能力

### Requirement: 受预算约束的上下文组装
每次模型调用前，系统 MUST 通过独立 Context Assembler 按活动模型的上下文预算组装临时输入。组装顺序 MUST 优先保留系统与任务约束、当前会话硬约束和最近消息，再选择版本化摘要、相关用户记忆和相关公共 Evidence；低置信度推断记忆 MUST NOT 挤出更高优先级约束。组装结果 MUST 记录所用来源记录和版本，但不得把框架专用消息格式保存为产品记忆权威。

#### Scenario: 上下文超过模型预算
- **WHEN** 最近消息、摘要、相关记忆和 Evidence 的总量超过活动模型预算
- **THEN** Context Assembler MUST 按稳定优先级裁剪或摘要低优先级内容，并保留当前硬约束及可追溯的组装记录

#### Scenario: 更换 Agent 或模型适配器
- **WHEN** 运行时切换到另一个满足相同能力合同的 Agent 或模型适配器
- **THEN** 权威会话与记忆记录 MUST 保持可用，只允许边界适配器转换临时模型消息格式
